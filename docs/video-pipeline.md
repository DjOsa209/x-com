# 分镜编排与拼接

2026-10-19。对应本项目的可运行实现，采用 Clipcat 公开前端已证实的“分镜确认 → 视频任务 → 拼接状态”流程。Clipcat 的服务端切分、模型调用和拼接算法仍未公开；下述策略、首帧生成和 FFmpeg 实现属于 X-Ecommerce 自己的实现。

## 使用

1. 在「连接与设置」配置 Gemini（分析/分镜），以及 fal.ai 或 Kie.ai（视频）。Kie 默认直接使用商品图首帧，无需 fal；选择 AI 场景首帧则另需 fal。详见 [Kie 接入](./kie-integration.md)。TikTok 分享链接的解析另需 EchoTik，上传参考视频则不需要此解析服务。
2. 工作台选择「商品转视频」或「一键复刻」，提供商品图、要求和可选参考视频，选择模型、时长和分段策略，创建项目。
3. 在「项目与分镜」生成分镜，展开逐镜编辑修改时间、画面及口播。时间轴须从 0 开始、连续、无重叠，并覆盖目标总时长。没有时间的镜头会等分，并显示提示。
4. 预览每段起止、保留秒数、模型生成秒数、预计调用数。可确认 1–4 个完整视频版本；版本数量不是片段数量。修改后自动重新预览，确认时检查计划指纹，配置发生变化则重新确认。
5. 后台按段生成首帧与视频、保存片段，再裁切、统一画幅/帧率/音轨并拼接，保存成片后才显示完成。任务页和项目详情展示逐段进度。

未配置密钥时可编辑/预览计划，实际生成会明确报错。没有伪造数据或直接把请求成功视为成片。

## 模型与策略

设置页可编辑默认模型 ID、策略、每段秒数、片段上限，以及高级模型目录 JSON。任务创建/项目确认时保存模型端点、能力、首帧模型和策略快照；后续修改设置不改变已排队的执行计划。

| 配置键                         | 默认                                    | 作用                                                 |
| ------------------------------ | --------------------------------------- | ---------------------------------------------------- |
| `VIDEO_DEFAULT_MODEL`          | `kling-standard`                        | 默认注册模型 ID                                      |
| `VIDEO_SEGMENT_STRATEGY`       | `balanced`                              | 分段策略                                             |
| `VIDEO_SEGMENT_SECONDS`        | `8`                                     | 每段目标时长，1–30；仍受模型上限限制                 |
| `VIDEO_MAX_SEGMENTS`           | `12`                                    | 每条视频最多片段数，1–20                             |
| `VIDEO_MODELS_JSON`            | Kling Standard/Pro、Kie Veo Fast / Mini | 渠道、模型端点、适配器、时长、画幅、分辨率及角色能力 |
| `FAL_IMAGE_EDIT_MODEL`         | 见设置                                  | 每段商品首帧模型，任务创建时同样固定                 |
| `FFMPEG_PATH` / `FFPROBE_PATH` | npm 包自带二进制                        | 服务器环境变量，可覆盖可执行文件路径                 |

模型目录仅用于有对应输入适配器的端点，不能仅换名称就适配任意服务。fal 保留 `kling-v3` 和 `veo31` 输入适配器，默认 Kling Standard/Pro，时长为 3–15 整秒。新增 Kie `kie-veo-fast`（4/6/8 秒）和 `kie-seedance-mini`（4–15 秒）。fal Veo 仍需自行核对兼容端点后登记。已公告淘汰的端点没有加入默认目录。旧 `FAL_VIDEO_MODEL` 在未修改默认目录时兼容覆盖 Standard 端点，仍须符合 Kling v3 schema；建议使用新的模型目录。Kie 的能力与限制见 [接入说明](./kie-integration.md)。

| 策略       | 行为                                       |
| ---------- | ------------------------------------------ |
| `balanced` | 尽量把完整镜头装入每段；超长镜头按上限切开 |
| `shots`    | 每个镜头独立生成；超长镜头继续分段         |
| `fixed`    | 按固定秒数切分，可能跨镜头                 |
| `single`   | 整条单次生成，超过模型原生上限就拒绝       |

总时长 1–120 秒。每段模型时长向上取支持值，例如保留 2 秒的片段会调用 3 秒模型，再保留前 2 秒。预览显示此差额。fal 默认每段 1 次首帧 + 1 次视频调用；Kie 默认商品图直用，每段 1 次视频调用，也可选择额外 AI 首帧。分镜/分析、失败重试、超分另计。平台额度为每次任务的内部额度，重试创建新任务并预留额度，不代表供应商费用估算。

## 执行和恢复

- `jobs.provider.name=video-pipeline`：保存完整计划、逐段请求 ID、阶段、素材引用、错误和 `concatStatus`。每个片段阶段分别为准备、提交首帧、首帧生成、准备视频、提交视频、视频生成、片段完成。现有 MySQL worker 锁和任务锁保护推进。
- 在可能付费的提交前先记录提交意图。通过自定义传输关闭 fal SDK 的提交隐式重试（仅设置 `config.retry` 会被 SDK 的 queue.submit 覆盖）。超时/重启导致提交结果不明确且没有请求 ID 时，进入待核对，禁止自动重发。有请求 ID 的轮询错误恢复后继续查询同一个请求。
- 明确失败重试复用已成功片段；视频提交失败但首帧已保存时复用首帧。拼接探测发现某段过短或无视频轨道时，仅将该段标为失败，重试复用其首帧及其他成功片段。只有拼接失败时不调用模型，已移除生成凭证也可重试本地拼接。对同一个失败任务重复请求重试返回同一个重试任务。
- 平台管理员可在供应商核查后通过已有人工核对接口标记失败并保留审计备注；普通工作空间管理员不能解除待核对费用。人工判断不替代供应商确认。
- 取消后停止未提交片段，已发出的请求尝试取消并继续核对，供应商已执行的任务仍可能产生费用。
- 最终素材采用任务 ID + 合成签名定位，拼接结果已保存而完成状态写入中断时可复用。旧版 `fal` 两阶段任务继续由原轮询逻辑处理；高级 raw 生成保持直接提交。

## 拼接

使用 FFmpeg/FFprobe（安装 npm 依赖时获得二进制，可配置自有路径）。生成前检查工具可用性。仅从本地已验证素材读取；探测视频轨道和时长后，逐段裁切、等比缩放补边、统一为 24fps / H.264 / yuv420p / AAC / 48kHz 双声道，无声片段补静音，按顺序输出 MP4。不会拉伸商品画面。成片按所选画幅与分辨率输出，检查时长和 100MB 上限，临时文件结束后清理。

当前为硬切。没有额外的全片 TTS、背景音乐混音、自动转场或声音克隆。各段原生口播及人物连续性取决于模型和参考图；跨长镜头切分时会提示人工检查接续，不能保证完全连续或保证销售效果。没有真实密钥，因此尚未验证真实模型的质量、耗时和费用。

## 接口与验证

- `GET /api/video/models`：当前空间模型目录与默认策略。
- `POST /api/video/plan`：`{input,storyboard}`，纯计划校验，无外部调用；返回 `segments`、`warnings`、`providerCalls`、`fingerprint`。
- `POST /api/projects/:id/confirm`：已有确认参数加 `renderOptions` 和可选 `planFingerprint`。完整确认分镜与执行快照写入每个视频任务。
- `GET /api/jobs` / 项目详情：新增安全的 `pipeline` 进度视图，不返回凭证。
- `POST /api/jobs/:id/retry`：失败/已取消任务创建可恢复的重试任务。

执行 `npm test`、`npm run test:video`、`npm run test:backend`。视频集成测试使用真实 MySQL、真实 FFmpeg 和离线注入的模型队列：不同尺寸/帧率/有声及无声视频、裁切与顺序、时长/音轨、失败重试、无凭证本地重拼及重试幂等。测试持有 worker 锁，结束后清理自身记录/文件，不请求真实模型。

模型 schema 核对来源：[Kling v3 Standard](https://fal.ai/models/fal-ai/kling-video/v3/standard/image-to-video/api)、[Kling v3 Pro](https://fal.ai/models/fal-ai/kling-video/v3/pro/image-to-video/api)、[Veo 3.1 Fast](https://fal.ai/models/fal-ai/veo3.1/fast/image-to-video/api)。具体 API 可用状态应以部署时供应商资料为准。
